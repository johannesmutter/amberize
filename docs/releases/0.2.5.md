# Amberize 0.2.5

This release fixes the Linux AppImage launcher permissions that prevented normal users from starting version 0.2.4. The AppImage catalog exposed a root-owned `AppRun.wrapped` with mode `0770`; the build-user checks had missed the failure. The launcher is now prepared with verified upstream bytes and mode `0755` before packaging and signing. Release checks reject unreadable files or launchers and execute the root-owned package under a separate user.

Linux packages are built on Ubuntu 22.04, and the AppImage's bundled ELF files are checked for glibc requirements no higher than 2.35. This reduces the previous 2.39 requirement. Linux still needs compatible system services and graphics libraries; AppImage does not bundle the operating system's C library.

The archive, sync and desktop source is unchanged from 0.2.4; Mac and Windows are rebuilt with the new release version. The recovery, background-performance and export improvements from 0.2.4 are included. Google continues to use a user-supplied Desktop OAuth client. Existing manual coverage limits remain documented in the 0.2.4 release notes.
