# Amberize 0.2.7

This release fixes Linux AppImage startup permissions and archive file checks that could release SQLite's database locks on macOS and Linux. Archive reopening, manual sync and protected export checks now compare filesystem metadata without independently opening and closing the database. SQLite validates the archive through its non-creating connection before applying write settings, preserving empty and unrelated database files when they are rejected. The existing connection cache and protection against exporting over archive aliases are retained.

The AppImage launcher is prepared with verified upstream bytes and mode `0755` before packaging and signing. Release checks inspect stored permissions and run the root-owned package under a separate user. Linux builds use Ubuntu 22.04 and reject bundled ELF requirements above glibc 2.35, reducing version 0.2.4's 2.39 requirement. Compatible system services and graphics libraries remain necessary.

This release includes all recovery, background-performance and export improvements from 0.2.4. Google continues to use a user-supplied Desktop OAuth client. Existing manual coverage limits remain documented in the 0.2.4 release notes.
