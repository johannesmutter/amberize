# Amberize 0.2.4

This release repairs archive recovery, background startup and credential persistence, and reduces resource use when the window is closed.

- Saved archive settings are written atomically. Missing, unavailable or damaged archives retain their saved path and show recovery actions instead of silently creating an empty archive.
- Windows and Linux use persistent system credential storage. Startup registration refreshes its executable path, and macOS can reopen the window after its WebView has been released.
- Closed windows release WebContent while background polling continues. Indexed pagination, bounded message fetches and streaming exports reduce unnecessary work and allocations.
- Selected-message exports contain only the selected messages. Exports preserve the previous output on cancellation, failure or insufficient disk space, and cannot overwrite the source archive.
- Provider timeouts, interrupted imports, oversized-message handling, OAuth cancellation and sync-status messages are more reliable. Google client fields now follow the app's light and dark themes.
- Updated dependencies and release checks include signed updater verification and notarization of both macOS apps and DMG containers.

Existing archives remain in place and upgrade automatically. Back up an archive before downgrading; older releases may not understand the upgraded schema.

Windows/Linux users upgrading from 0.2.3 may need to enter account credentials again once: the old credential adapter did not persist them. Version 0.2.4 stores newly entered credentials in the operating system's persistent secure store; Linux requires an available Secret Service.

Google sign-in continues to use a user-supplied Google Desktop OAuth client. The client owner's Google project controls consent branding, verification and access limits. This release does not offer a shared verified Google client; it still uses Gmail's full-mail IMAP permission. Public shared sign-in with narrower Gmail API access is separate follow-up work. The local browser callback uses HTTP on 127.0.0.1; Google authorization and token requests use HTTPS.

Validation includes cross-platform tests, installer/recovery checks, signed updates from an older release, actual Windows/Linux reboot and login, live IMAP attachment delivery, and full Gmail import with continued scheduled polling and content-hash verification. Native Mac light/dark client-field rendering and launch-at-login enable/disable passed in an isolated build of the same product source. Remaining manual coverage includes a working-Mac OS reboot, fresh browser-quarantined Mac first launch, Windows SmartScreen/checkbox behavior, the native full-auditor export/cancel flow and controlled new Gmail attachment delivery. These checks are recorded as unverified, not passing. The signed stable artifacts are assessed before publication.
