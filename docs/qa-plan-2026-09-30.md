# Pre-release validation

The user approved executing the proposed pre-release testing process on 2026-09-30. Keep all releases unpublished. Preserve the active checkout, existing application data, credentials, and current host session. Use temporary archives and isolated configuration directories or dedicated test users. Never reboot the working Mac as part of unattended testing.

## Candidate and automated gate

Capture the current reviewed repairs and packaging changes in an isolated Git checkout. Give the candidate a prerelease version, record its exact commit, push a `codex/` branch, and run the existing macOS, Windows, Linux, frontend, and Python CI checks. Build signed installers through the existing release workflow into a draft prerelease. Any failure blocks publication and must be investigated against its actual logs.

## Installed application and data preservation

Use synthetic archives and record message counts and MIME hashes before and after open, restart, upgrade, export, and recovery. Exercise saved path restoration, an unavailable archive and its return, interrupted writes, selected and full exports, cancellation, filter pagination, preview selection, remote-image consent, and repeated close/reopen. Validate native background startup and window release. Measure release-mode process memory and CPU with the window open and after it has been closed long enough to release the webview. Include child WebKit processes and repeated cycles in the measurements.

Test macOS installer signing and notarization independently of local development builds. Test Windows and Linux installers in accessible isolated environments. Perform login/reboot testing only inside a disposable or explicitly dedicated test environment; record missing environments as unverified. Do not equate compilation or unit tests with successful native installation, login startup, or provider integration.

## Providers and update path

Request a dedicated test mailbox and interactive Google consent; do not request secrets in chat or read existing personal credentials. Exercise offline/reconnect, interrupted and oversized message handling, credentials after process restart, and delivery while the window is closed. Test the signed update from an older version through a separate test endpoint and test installation, archive preservation, and rollback availability. Never change the production updater endpoint or publish a candidate to make this test possible.

## Evidence and release decision

Save exact commands, candidate commit, CI and draft URLs, fixture checks, signing assessment, and process measurements. Classify each gate as passed, failed, or awaiting a specific external prerequisite. Publication requires passing CI and supported-platform installer, data preservation, startup, provider, background resource, and updater checks. Passing a subset does not constitute release approval.
