# Amberize repair results — 2026-09-30

All 25 numbered findings were checked again against the original code and their relevant callers. Their underlying defects were confirmed; several broader claims required qualification. Repairs are implemented locally. Native platform and provider validation remains narrower than source/test coverage, as recorded below. Existing AppImage packaging changes, CLI 2.11.4, and catalog retest instructions were preserved. No live archive, credential entry, login registration, release, or deployment was changed during validation.

## Before publishing

Test actual installers on macOS/Windows/Linux: restart and login after moving/updating the app; credential persistence and unavailable credential-store recovery; duplicate launches; archive removal/reconnection; real IMAP failures, oversized mail and UIDVALIDITY changes; Google authorization/identity/cancellation with the supported client policy; external-image network requests before/after consent; signed updates and notarization. No release-readiness claim replaces those checks.

Measure the complete release-build process tree, including webview children, for visible/hidden idle, hidden sync, large MIME preview, repeated reopen cycles, and large exports. The implemented lifecycle removes a retained webview, but actual memory/energy savings and shared connection trade-offs remain unmeasured. A versioned incremental proof format, separate read pools, transaction batching and per-account retry schedules remain profiling-driven options rather than prerequisites for these repairs.
